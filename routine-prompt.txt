Republish the owner's Sable AI Ledger page with the newest page and data in this repository. The page is the private claude.ai artifact https://claude.ai/artifact/9rkccTsV3vvha7mtggGaTh, owned by the same account this routine runs as. A launchd job on the owner's Mac rebuilds out/*.json from their AI usage logs each morning and pushes it here; the owner also pushes page changes to ledger/index.html. Your only job is to publish them.

Steps:
1. Run `git rev-parse --is-shallow-repository`. If it prints true, run `git fetch --unshallow` so the full history of ledger/index.html is available.
2. Run `git log -1 --format='%h %cI %s' -- out` and note the result (the data commit).
3. Use the Artifact tool, action read, with url https://claude.ai/artifact/9rkccTsV3vvha7mtggGaTh. A publish to an artifact this session has not read is refused, so this comes first.
4. Artifact tool, action list, scope files, same url.
5. Artifact tool, action publish, with url https://claude.ai/artifact/9rkccTsV3vvha7mtggGaTh, file_path set to the absolute path of ledger/index.html in this checkout, label "Daily refresh <today's date, YYYY-MM-DD>", and files mapping each published path to its source in this checkout: data/daily.json -> out/daily.json, data/tasks.json -> out/tasks.json, data/prices.json -> out/prices.json, data/waveform.json -> out/waveform.json. Do not pass capabilities, icon, contract or force. If it succeeds, go to the last line.
6. If that publish is refused because the live page differs from the one you sent:
   a. Save the live page. Use the saved file path the refusal names, if it names one; otherwise use the Artifact tool, action read, same url, with path index.html, and use the file it saves.
   b. Run `python3 check_live.py <that path>` from the root of this checkout and note its output and exit code.
   c. Exit 0 means the live page is just an older commit of ledger/index.html. Send the publish from step 5 again with exactly the same arguments. If that is refused as identical content resent unchanged, send it once more, still with the same arguments. Never publish more than three times in total. If the third is refused too, stop and report the exact error.
   d. Exit 1 or 2: stop without publishing. Report check_live.py's output word for word. Do not describe or summarise the differences yourself.

Do not edit, commit or push any file, and do not create a new artifact: if a publish would go anywhere other than that url, stop. If any other call is refused or the Artifact tool is missing, report the exact error and stop. Finish with one line: the artifact version you published (or "not published"), the data commit from step 2, and check_live.py's output if you ran it.
